# What Specwright is

Specwright is a tool that orchestrates AI agents across a software project. It is not a language model. The model is called, through LangChain, by an agent node. The tool owns the order of the work, the pages, and the moment you decide.

The pass is the product. An idea prompt becomes a brief. A brainstorm keeps and discards options, including existing alternatives and a real-world use. A proposal states the core idea and the problem. Architecture records the core workflow, the system shape, and the stack. Requirements are testable and ordered into a roadmap. The team charter names expertise and duties for this project. Titles such as backend, frontend, AI, UX, architect, and DevOps are examples, not a roster every run fills. The repository step creates a folder you can read. The same charter then works the roadmap for one cycle.

You accept each stage. Agents write drafts. The story in `history/story.md` is the history you read. Git is not part of that reading.

The builder's path is the [product backlog](../reference/backlog.md). The learning journal records what the builder learned. Neither one replaces the product goal.

## Outcome

A fixture idea in. A folder out. The folder holds accepted pages, a charter, a story, and one cycle record. Search can point at a page in that folder or say that nothing accepted supports the answer.

## Who it is for

A person starting a project who should not have to staff agents by hand or read Git. The same person is the product owner of Specwright while it is being built: they order the backlog and accept increments.

## What this product refuses

It does not publish a page because an agent finished talking. It does not staff every specialist on every idea. It does not let the monitor add scope. It does not treat a session note as a decision.
